# Feature passports — current code, not imagined modules

Every owned top-level Android class has exactly one entry in `../owners.json`. Ownership changes and checker changes land together. `docs/architecture.md` describes the target direction; these passports name *current* entry points, public boundaries and the checks to run. Most UI is still Java/XML. Shared platform classes live in `core/`, `net/`, `store/`, `media/` and must not import feature UI. Compose migration must not hide transport or mutation inside composables.

| Owner | Current entry points | Public boundary and regression checks |
|---|---|---|
| **app-shell** | `PiApp` | Android process composition/lifecycle only. Never create a second Pi or store secrets in UI globals. See `android/app/src/androidTest/` and `docs/protocol.md`. |
| **catalog** | `MainActivity`, `ui/CatalogAdapter`, `ui/UsageCards`, `ui/ArchiveSheet` | Orca's authoritative visible layout, separate saved history, explicit destructive confirmation, honest usage. `CatalogParserTest`, `SessionGroupingTest`, Node `tests/archive.test.mjs`/`tests/usage.test.mjs`; synthetic `usage-redesign.png`. |
| **chat** | `ChatActivity`, `ui/MessageAdapter`, composer, status/Markdown/attachments widgets in `../owners.json` | One target Pi session, no automatic replay after uncertain ACK, chronological progress/tool segments, bounded media and persisted drafts. `ConversationFramesTest`, `TranscriptReconcilerTest`, `WorkTimelineTest`, `PayloadCodecTest`, `tests/conversation-sync.test.mjs`; baseline chat/header/attachment/tier PNGs. |
| **orchestration** | Kotlin/Compose `OrchestrationActivity.kt`, Java `ui/OrchestrationEntry` | Scoped read-only workflow and agent drill-down; saved state is never claimed live. Cards/header are Compose; nested transcript temporarily hosts `ui/MessageAdapter` via `AndroidView` (chat owner). `OrchestrationDataTest`, `OrchestrationUiTest`, `tests/orchestration.test.mjs`; three orchestration PNGs including narrow/large-font. |
| **voice** | `ui/DictationRecorder`, `ui/VoiceWaveform` | Local bounded PCM transcription returns draft text only; never auto-send a Pi command. `tests/speech.test.mjs`, `voice-recording.png` and Android UI checks. |
| **updater** | `ui/AppUpdates` | Independent unauthenticated GitHub client, SHA256/package/versionCode/signing-certificate checks, user-confirmed install. `ReleaseUpdateTest`, `docs/verification.md`. |
| **ui-foundation** | `ui/BubbleColors`, `ui/ExpressiveMotion`, `ui/FadeTextView`, `ui/SwipeAction`, `ui/SystemInsets` | Reusable styling/gesture/insets primitives, not feature/session ownership. Theme, accessible touch targets, IME/insets and both palettes must be checked on device. |

`store/SettingsStore`, `store/SecureTokenStore`, `store/ConversationCache` and `store/PendingMessages` own existing private data, not screen widgets; keep settings/token/cache after an in-place APK upgrade. `net/PiClient` owns the WSS connection and commands; `net/HttpApi` owns bounded HTTP; `core/` owns parsed wire data and reconciliation. For any new screen API, add tests covering authorization, stale/unknown ACK and offline state as appropriate. Android Compose is presentation only; mutation still flows through validated net/core policies. Follow the goal's M0–M6 parity gates rather than declaring a passport itself to be a migrated feature.

Host passports: `server/gateway.mjs` owns loopback binding, bearer/Origin checks, WS command dispatch and bridge owner; `server/command-policy.mjs` owns bounded command/image validation; `server/message-projection.mjs` owns ordered/sanitized transcript rows; `server/media-cache.mjs` owns per-session-scoped image bytes with FIFO eviction; `server/session-projection.mjs` owns configuration/page/snapshot allowlists; `server/orchestration.mjs` owns confined read-only agent snapshots; `contracts/agent-transcript.mjs` owns pure transcript projection and is the only intentionally shared implementation. Extension `extension/mobile.ts` alone can touch a live Pi runtime. `npm run check:architecture` enforces the current lane direction, while Node tests cover auth, restart, bounded media, transcript and agent ownership.
