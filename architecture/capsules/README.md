# Feature passports — current code, not imagined modules

Every owned top-level Android class has exactly one entry in `../owners.json`. Ownership changes and checker changes land together. `docs/architecture.md` describes the target direction; these passports name *current* entry points, public boundaries and the checks to run. All production Android source is Kotlin; screens and modal content use Compose, with bounded native Markdown/zoom/modal hosts. Shared platform classes live in `core/`, `net/`, `store/`, `media/` and must not import feature UI. Compose migration must not hide transport or mutation inside composables.

| Owner | Current entry points | Public boundary and regression checks |
|---|---|---|
| **app-shell** | `PiApp` | Android process composition/lifecycle only. Never create a second Pi or store secrets in UI globals. See `android/app/src/androidTest/` and `docs/protocol.md`. |
| **catalog** | `MainActivity.kt`, `features/catalog/CatalogSession`, `features/catalog/CatalogScreen`, `ui/UsageCards`, `ui/ArchiveSheet` | Injected catalog owner and Compose drawer/grouped settings; Orca's authoritative layout, scoped confirmed mutations, lifecycle generations, separate paginated history and honest usage. `CatalogSessionTest`; `CatalogParserTest`, `SessionGroupingTest`, Node `tests/archive.test.mjs`/`tests/usage.test.mjs`; synthetic `usage-redesign.png`. |
| **chat** | Kotlin shell `ChatActivity`, `features/chat/ChatSession`, `features/chat/ChatOutbox`, Compose `features/chat/ChatScreen`, public `ui/PiTranscript`, Compose `ui/EffortSlider` | One target Pi session. ChatSession owns canonical state, scoped ACK/control/configuration/history, epochs and follow-tail through an injected transport. ChatOutbox alone owns receipts, retained bytes and manual retry/restore; reconnect cannot replay a prompt. ChatScreen owns presentation and invokes explicit platform callbacks. PiTranscript's optional actions enable local thumbnails/retry/restore/documents only for the main chat. Model/tier settings and anchored effort panel have Compose content; both share the brain slider through a bounded FrameLayout host. No feature/session ownership. Theme, accessible touch targets, IME/insets and both palettes must be checked on device. |

`owners.json` also registers `publicFeatureApis` at file scope and the four `compositionRoots`. Cross-feature calls use those named facades; Activity navigation belongs to composition roots. `PiTranscript` intentionally exports its callback contract alongside the renderer. Shared `ui/` is a namespace, not permission to reach another feature's implementation: the checker resolves registered filenames and top-level Kotlin exports, including wildcard imports, aliases and qualified references. Shared UI foundation cannot consume feature facades. `platformInteropDependencies` names only the existing ImageViewer/ArchiveSheet dependency on PiApp; it is not a general escape hatch. These source checks supplement the compiler and behavior tests; they do not resolve reflective calls or replace Kotlin's type system.

`store/SettingsStore`, `store/SecureTokenStore`, `store/ConversationCache` and Kotlin `store/PendingMessages`/`store/PendingMessageCodec` own existing private data, not screen widgets; keep settings/token/cache after an in-place APK upgrade. `net/PiClient` owns WSS and commands; `net/HttpApi` owns bounded HTTP; `core/` owns parsed wire data and reconciliation. `TranscriptPresentation` owns legacy normalization, independent tool segments and one-time settlement; repeated snapshots preserve manual disclosure. `PiTranscript` has no transport dependency: optional main-chat actions are callbacks to the owner, while omitted actions preserve read-only inspection. Legacy chat/catalog adapters and screen XML were removed with their callers. Only the image-viewer close-button layout remains as documented native interop; resource vectors/themes are not screen layouts. New APIs must verify authorization, stale/unknown ACK and offline state. Compose is presentation; mutation flows through validated feature/net/core policies. Follow M0–M6 gates; this map does not establish completed migration or physical-device parity.

Host passports: `server/gateway.mjs` owns loopback binding, bearer/Origin checks, WS command dispatch and bridge owner; `server/command-policy.mjs` owns bounded command/image validation; `server/message-projection.mjs` owns ordered/sanitized transcript rows; `server/media-cache.mjs` owns per-session-scoped image bytes with FIFO eviction; `server/session-projection.mjs` owns configuration/page/snapshot allowlists; `server/orchestration.mjs` owns confined read-only agent snapshots; `contracts/agent-transcript.mjs` owns pure transcript projection and is the only intentionally shared implementation. Extension `extension/mobile.ts` alone can touch a live Pi runtime. `npm run check:architecture` enforces the current lane direction, while Node tests cover auth, restart, bounded media, transcript and agent ownership.
