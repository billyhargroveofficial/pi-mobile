# Feature passports — current code, not imagined modules

Every owned top-level Android class has exactly one entry in `../owners.json`. Ownership changes and checker changes land together. `docs/architecture.md` describes the target direction; these passports name *current* entry points, public boundaries and the checks to run. All production Android source is Kotlin; screens and modal content use Compose, with bounded native Markdown/zoom/modal hosts. Shared platform classes live in `core/`, `net/`, `store/`, `media/` and must not import feature UI. Compose migration must not hide transport or mutation inside composables.

`owners.json` also registers `publicFeatureApis` at file scope and the four `compositionRoots`. Cross-feature calls use those named facades; Activity navigation belongs to composition roots. `PiTranscript` intentionally exports its callback contract alongside the renderer. Shared `ui/` is a namespace, not permission to reach another feature's implementation: the checker resolves registered filenames and top-level Kotlin exports, including wildcard imports, aliases and qualified references. Shared UI foundation cannot consume feature facades. `platformInteropDependencies` names only the existing ImageViewer/ArchiveSheet dependency on PiApp; it is not a general escape hatch. `sourceContracts` adds bounded import/qualified-reference profiles and prevents reversed profiled state/projection/screen dependencies, including same-package symbols. Profiled inspector/catalog/configuration/updater/recording/transcription/attachment/document/composer/transcript state cannot import Android/UI/transport/storage, java.net or OkHttp; presentation forbids java.io and media operations except the Attachment data leaf; its sole net leaf is MediaLoader. Pure projections also forbid java.net/OkHttp. Unknown contracts and unowned contract sources fail closed. These source checks supplement the compiler and behavior tests; they do not resolve reflective calls or replace Kotlin's type system.

`store/SettingsStore`, `store/SecureTokenStore`, `store/ConversationCache` and Kotlin `store/PendingMessages`/`store/PendingMessageCodec` own existing private data, not screen widgets; keep settings/token/cache after an in-place APK upgrade. `net/PiClient` owns WSS and commands through a scoped `PendingCommands` ledger; `net/HttpApi` owns bounded HTTP; `core/` owns parsed wire data and reconciliation. `core/AgentMetrics` owns nullable static tool/token aggregation. `TranscriptPresentation` owns legacy normalization, independent tool segments and one-time settlement; repeated snapshots preserve manual disclosure. `PiTranscript` has no transport dependency: optional main-chat actions are callbacks to the owner, while omitted actions preserve read-only inspection. Legacy chat/catalog adapters and screen XML were removed with their callers. Only the image-viewer close-button layout remains as documented native interop; resource vectors/themes are not screen layouts. New APIs must verify authorization, stale/unknown ACK and offline state. Compose is presentation; mutation flows through validated feature/net/core policies. Follow M0–M6 gates; this map does not establish completed migration or physical-device parity.

Active chat work facts are shared through pure `core/ActiveWork`, not by reaching another feature implementation. ChatScreen projects one snapshot for header/composer/dock, preserving the public JSON screen API. `ui/OrchestrationEntry` retains lifecycle discovery and both public ActiveOrchestration adapters; internal `features/orchestration/ActiveWorkScreen` owns existing compact/expanded geometry and the elapsed ticker. Projection owns copied phase/agent/workflow facts, static counters, primitive clocks, scoped navigation targets and history/live membership; it retains no source JSON. Published lists are read-only. Timer labels read no source facts after projection. `ActiveWorkTest`, source-direction checks, `ActiveWorkUiTest`, existing runtime counters, workflow/keyboard/inspector/composer and arrival regressions guard this contract; [checks/limits](../../docs/architecture-active-work-20261008.md).

The local transcript-image slice adds internal platform-free `features/chat/TranscriptImageSession` and presentation-only `TranscriptImageScreen`. Public `ui/PiTranscript` keeps TranscriptActions, read-only inspection, MediaLoader and native ImageViewer adapters. A binding belongs to both URL and loader identity; replacing the loader starts clean even with an unchanged URL. Reservation precedes the load port, only the first result publishes, and local retirement releases its reference while rejecting late callbacks without recycling shared cache pixels or cancelling another subscriber. Local attachment URLs never load remotely. Compose pixels retain the original aspect/size/feedback; fullscreen opening remains an injected callback. [Verification and limits](../../docs/architecture-transcript-image-20261008.md).

Host passports: `server/gateway.mjs` owns loopback binding, bearer/Origin checks, WS command dispatch and bridge owner; `server/command-policy.mjs` owns bounded command/image validation; `server/message-projection.mjs` owns ordered/sanitized transcript rows; `server/media-cache.mjs` owns per-session-scoped image bytes with FIFO eviction; `server/session-projection.mjs` owns configuration/page/snapshot allowlists; `server/orchestration.mjs` owns confined read-only agent snapshots; `contracts/agent-transcript.mjs` owns pure transcript projection; `contracts/command-receipts.mjs` owns bounded mutation-only deduplication shared by gateway and extension. Read payloads are never retained. Extension `extension/mobile.ts` alone can touch a live Pi runtime. `npm run check:architecture` enforces the current lane direction, while Node tests cover auth, restart, bounded media, transcript and agent ownership.
