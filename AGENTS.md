# Pi Mobile — инструкция для агентов

Сначала читай `README.md`, текущий код/тесты и `docs/protocol.md`. Для явно запрошенной долговременной миграции читай `loop-develop/README.md` и единственный активный `loop-develop/current-todo/001-todo.md`. Наличие goal-файла само по себе **не запускает** переписывание проекта.

Продукт — мобильное окно в **существующий** Pi в Orca, не отдельный агент. Никогда не завершай, не перезагружай и не подменяй работающий Pi ради теста; `/reload` допустим только когда владелец подтвердил, что сессия idle. Не запускай платные промпты для UI-тестов. Gateway слушает loopback, устройство подключается по HTTPS; не выводи токены, не клади их в APK и не ослабляй read-only inspection.

Дизайн, который уже работает, — baseline: нейтральная тема, единый Usage, компактная однострочная шапка чата, сообщения и сгруппированные инструменты, пропорциональные вложения/zoom, workflow drill-down, доступный composer. Миграция в Kotlin/Compose не разрешает менять пользовательскую иерархию наугад. Сначала baseline-скриншоты и сценарии; затем проверяемое улучшение, включая узкий экран, крупный шрифт и тёмную тему.

`nareshka-mono` — **только reference для принципов** agent-readable архитектуры (тонкий shell, владельцы-капсулы, публичные контракты, fail-closed checks), не источник кода и не объект правок. Делай последовательные вертикальные слайсы с собираемым Android в каждом, не big-bang rewrite. README/docs — стабильные факты и ограничения, `loop-develop/current-todo/` — активный goal.

Текущий базовый gate: `npm test`; `cd android && ./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest` с JDK17/Android SDK; ADB/UiAutomator для интерфейса. Перед релизом проверь versionCode, прежний signing certificate, APK SHA256, upgrade без удаления данных и правильный Telegram-чат. По просьбе Billy после **кодовых** правок и тестов выпускать обновление сразу; создание/редактирование одного goal-документа APK не требует.
