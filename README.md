# Pi Mobile — Android companion for Pi in Orca

Нативный Android-клиент для **того же процесса Pi**, который открыт в Orca на Mac или Linux. Не трансляция терминала и не отдельный облачный агент: сохраняются контекст, инструменты и расширения рабочего Pi.

## Версия 0.6.003

- В чате появилась **Orchestration**: живые workflow с этапами и состояниями, отдельные агенты и вложенные дети. Переходы: workflow → агенты → внутренний диалог, инструменты и результат, только просмотр.
- Модель, effort, время, выходные токены и статусы показываются из фактического состояния, без выдуманных процентов. Обновление раз в2–3 секунды; завершённые записи сохраняются приватно. Если live-наблюдатель недоступен, сохранённая история помечена как история, а не как текущая работа.
- Для живых этапов установленная версия `pi-subagents` требует узкого совместимого read-only наблюдателя; он включён на Mac, но **уже работающие Pi не перезагружены**. В другом окружении см. [docs/setup.md](docs/setup.md).

- Промежуточные сообщения ассистента всегда открыты. Блоки инструментов сворачиваются с анимацией, без стрелки. Индикаторы начальной загрузки и догрузки истории.

### Сохраняемые возможности

- Каталог открытых Pi-вкладок и сплитов Orca; видны и пустые пространства. **«+» у пространства** создаёт настоящий новый Pi в новой вкладке, без отправки промпта.
- **Свайп влево по живой сессии → закрытие её терминала** после подтверждения. Для работающего Pi явно подтверждается прерывание; история остаётся на диске.
- **История:** даты, поиск, постраничная загрузка и скелетоны той же геометрии, что карточки. Выбор возобновляет сохранённый диалог в Orca; свайп удаляет **файл истории с диска** после отдельного необратимого подтверждения. Живые/неоднозначные сессии защищены от удаления.
- Хронологическая цепочка **инструменты → отдельное progress-сообщение → инструменты**. Steer разделяет ходы; при завершении блоки инструментов автоматически сворачиваются и независимо раскрываются по нажатию. Промежуточные сообщения остаются открытыми. Финальный ответ — отдельно. Аргументы читаемые, без сырого JSON.
- Затухание сверху переписки; индикатор Working с реальным временем на нижнем градиенте.
- Четыре кнопки composer: вложение, **Queue / Steer**, effort и отправка (микрофон при пустом вводе). Пружинный effort-слайдер с реальными touch-жестами. Effort можно менять во время работы; модель — только у свободного Pi. Глобальные defaults не меняются.
- `$`-подсказки навыков из реального registry, `/mcp` — состояние подключений, `/name` — имя Pi-сессии. Для новых возможностей требуется обновлённое расширение.
- Нативные Markdown, таблицы, LaTeX, просмотр `.md`, картинки и полноэкранный zoom; светлая и тёмная темы.
- Прикрепляются не только изображения, но и обычные файлы: компактные chips до отправки, реальные приватные файлы на хосте для инструментов Pi. Две маленькие галочки означают приём сообщения, **не завершение задачи**.
- Диктовка до10 минут: текст попадает в composer без автоматической отправки. Использует локальные sherpa-onnx и Parakeet v3, уже установленные Orca; ключи облачных STT не нужны. На Linux требуется указать пути к движку/модели.
- Исправлены прыжки прокрутки и загрузка длинных ходов: предыдущие страницы догружаются до сообщения пользователя. Неподтверждённые сообщения сохраняются при повторном входе, без автоматического повтора.
- Gateway для macOS (LaunchAgent) и Linux (systemd user), в том числе HTTPS через Tailscale Funnel с префиксом пути.

## Установка и подключение

1. Скачать **`Pi-Mobile-0.6.003.apk` из Releases этого репозитория** и установить на Android. Это персональная debug-сборка, не Play Store; APK не содержит токенов.
2. Настроить компьютер по **[docs/setup.md](docs/setup.md)**: Pi, расширение, Orca, loopback gateway и HTTPS.
3. На телефоне указать HTTPS URL своего gateway и секрет из `~/.pi/agent/pi-mobile/device-token` **на том же компьютере**. Mac и Linux имеют отдельные токены; автоматически они не синхронизируются.
4. Существующие Pi обновлять командой `/reload` **только после окончания их работы**. Новые процессы загружают расширение автоматически. Проверка: `/mobile status`.
5. Выбрать сессию, нажать «+» либо открыть «Историю». Терминалы без моста помечены как требующие расширение.

Компьютер должен быть включён, Orca — запущена в пользовательской desktop-сессии. Телефон не заменяет хост. Произвольные approval-диалоги расширений остаются на компьютере.

## Архитектура

`Android (HTTPS/WSS) → HTTPS proxy → loopback Node gateway → private Unix socket → Pi extension → живой агент`

- `extension/` — история активной ветки, live-события, адресные команды, навыки и MCP.
- `server/` — авторизация, Orca inventory, lifecycle сессий, сохранённая история и картинки.
- `android/` — выпущенная версия на Java/native Android views, Material 3 Expressive, RecyclerView, OkHttp, Android Keystore. Локально идёт поэтапная миграция на Kotlin/Compose; выпускаемая версия пока не изменена.

## Разработка

Требуются Node ≥22.18, установленный Pi, JDK17 и Android SDK. Пути SDK/JDK ниже — пример для Mac.

```sh
npm ci
npm run quality
cd android
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
export ANDROID_HOME="$HOME/Library/Android/sdk"
./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w ru.billyhargrove.pimobile.test/androidx.test.runner.AndroidJUnitRunner
```

Проверять итог `OK (…)` instrumentation: ADB может завершиться с кодом 0 даже при провале тестов. UI-тесты не отправляют промпты реальным агентам и не закрывают их.

Эмулятор: `./scripts/emulator.sh start|install|stop`; UI через `scripts/android-ui.py`. По умолчанию GPU `auto`; программный режим задаётся явно через `PI_MOBILE_GPU` и может сильно нагружать CPU. Debug допускает HTTP для эмулятора; на телефоне использовать HTTPS.

## Безопасность

- Gateway слушает `127.0.0.1:8788`; приватная папка 0700, token/socket 0600. Все API, WSS и картинки требуют bearer; `/health` открыт без содержимого сессий. Токен не передаётся в URL; браузерные Origin отклоняются.
- **Токен даёт управление агентами и их инструментами, включая закрытие процессов и удаление сохранённых сессий.** Хранить как пароль, не коммитить и не встраивать в APK. У каждого хоста свой секрет.
- После обрыва команды не переотправляются автоматически. При неизвестном результате сначала проверить Orca; сохранённые намерения запуска защищают от двойного процесса даже после перезапуска relay.
- Отзыв доступа: заменить `device-token` криптографически случайным секретом (≥32 символов), сохранив права 0600, перезапустить gateway и обновить доверенные устройства.
- Это персональный инструмент, не многопользовательский сервис; независимый security-аудит не проведён.

## Ограничения

- Live-визуализация workflow требует совместимого read-only наблюдателя в `pi-subagents` 0.19.0 и безопасного `/reload` после завершения работы существующей Pi-сессии. До этого доступны только найденные сохранённые данные (не все workflow-фазы и не все дочерние диалоги). Основной интерфейс переведён на английский; часть технических ошибок и старых сообщений gateway пока остаётся на русском.
- **Fork и синхронизация `/name` с заголовком вкладки Orca пока не реализованы.** `/name` меняет имя самой Pi-сессии.
- История: стандартное хранилище Pi известных локальных пространств, не произвольные `--session-dir` и не удалённые Orca-хосты. Неизвестный Pi без моста в пространстве блокирует небезопасное возобновление/удаление.
- Начальная история — последние40 исходных сообщений, далее порциями40. Если хвост состоит только из инструментов, клиент автоматически догружает страницы до сообщения пользователя; более старые страницы — при прокрутке вверх. Кеш хранит до8 диалогов по2MiB на диске до7 дней, без файлов изображений. При несовместимом или отсутствующем checkpoint после reconnect выполняется полная загрузка; длинные записи ограничены и помечаются как обрезанные. Вложенный tool output, не записанный Pi в историю, доступен только live.
- Effort меняется для последующих запросов, уже отправленный запрос провайдеру не пересоздаётся. Старое загруженное расширение может отклонять изменения во время работы до безопасного `/reload`.
- `.md`/`.markdown`: только внутри реальной папки сессии, до1MiB, без выхода через симлинки, HTML/JS и автозагрузки внешних картинок. LaTeX — поддерживаемое подмножество, не полный TeX.
- До3 вложений (файлы + PNG/JPEG/WebP), суммарно10MB на сообщение. Файлы сохраняются в приватной `uploads/` gateway; лимит256MiB, при заполнении нужна ручная очистка уже ненужных файлов. Серверный кэш изображений128MB может вытесняться; zoom использует декодированное изображение до1600px по длинной стороне. При повторном входе текст неподтверждённого сообщения сохраняется, но для ручной повторной отправки вложения нужно выбрать заново.
- Метрики TPS вычисляются по реальным токенам и времени стрима без инструментов, не являются benchmark. Для старых ходов без метрик значения не выдумываются.
- Нет push-уведомлений, гарантированной background-связи Android и полного мобильного редактора Orca. При возвращении клиент переподключается.
