# Pi Mobile — Android companion for live Pi in Orca

Нативный Android-клиент на **Material 3 Expressive**, а не трансляция терминала. Сообщения поступают в **тот же процесс Pi**, который открыт в Orca, со всеми его плагинами и контекстом.

Версия 0.2: компактный каталог рабочих пространств, статус подключения сверху, светлая/тёмная темы, пружинные нажатия и переходы. Чат поддерживает текстовый стрим, раскрываемые tool calls с живым выводом и аргументами, картинки в обе стороны и полноэкранный просмотр с pinch/double-tap zoom. Модель и effort меняются через кнопку настроек в шапке чата, только у выбранного Pi и только между задачами. Доступные модели и уровни возвращает сам Pi; глобальные defaults не меняются.

## Подключение телефона

1. Установить `artifacts/Pi-Mobile-debug.apk` (тестовая debug-сборка, не Play Store).
2. Сервер: `https://billyhargrove.ru`.
3. Токен взять **локально на Mac** из `~/.pi/agent/pi-mobile/device-token`. Скопировать без вывода в терминал: `pbcopy < ~/.pi/agent/pi-mobile/device-token`. Не отправлять токен в чаты/репозиторий.
4. В каждом **уже открытом** Pi после окончания текущей работы выполнить `/reload`. Новые процессы подхватят установленное расширение автоматически. `/mobile status` показывает состояние моста.
5. Выбрать workspace и сессию. Терминалы без расширения помечены «требуется расширение»; приложение не запускает для них второй Pi.

Mac должен быть включён, не спать и иметь доступ в Интернет. Gateway и HTTPS работают как пользовательские LaunchAgent после входа Billy. Это не независимый облачный хостинг.

## Архитектура

`Android (HTTPS/WSS) → Caddy → loopback Node gateway → private Unix socket → Pi extension → существующий агент`

- `extension/mobile.ts`: события Pi, активная ветка истории, отправка followUp/steer и abort.
- `server/`: каталог Orca, маршрутизация по session ID, авторизация, инкрементальные сообщения и отдельная выдача картинок.
- `android/`: Java/native Android views, OkHttp, RecyclerView; токен защищён Android Keystore.
- `docs/protocol.md`: транспортный контракт; `docs/verification.md`: выполненные проверки.

## Разработка и сборка

```sh
cd /Users/billy/repos/pi-mobile
npm ci
npm test
pi install /Users/billy/repos/pi-mobile
./scripts/install-service.sh
./scripts/install-https.sh

cd android
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
export ANDROID_HOME=$HOME/Library/Android/sdk
./gradlew testDebugUnitTest assembleDebug
# При запущенном эмуляторе (runner может удалить тестируемую APK после тестов):
./gradlew connectedDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

HTTPS-скрипт требует установленный `caddy`, DNS домена и проброс TCP 80/443. Текущая конфигурация персональная; для другого Mac/домена изменить Caddyfile и установочные параметры. После обновления Node при необходимости повторить установку LaunchAgent.

## Эмулятор и управление агентом

SDK: `~/Library/Android/sdk`; AVD: `PiMobile_API35` (ARM64, Android 15/API35, Pixel 7).

```sh
./scripts/emulator.sh start
./scripts/emulator.sh install
python3 scripts/android-ui.py dump
python3 scripts/android-ui.py tap settingsButton
python3 scripts/android-ui.py screenshot
./scripts/emulator.sh stop
```

Агент управляет реальным Android UI через ADB/UIAutomator: выбор файлов, ввод, нажатия и скриншоты. Для этого не нужен браузерный WebView или отдельный Android accessibility-сервис. Debug-сборка допускает также `http://10.0.2.2:8788`; на телефоне использовать HTTPS.

## Эксплуатация и безопасность

- LaunchAgent: `ru.billyhargrove.pi-mobile` и `ru.billyhargrove.pi-mobile-https`.
- Логи: `~/Library/Logs/PiMobile/`. Caddy автоматически обновляет сертификат.
- Шлюз слушает только `127.0.0.1:8788`. Токен и Unix socket доступны только владельцу (0600, папка0700).
- Все API/WS/картинки требуют bearer; `/health` открыт и не содержит данных. Токен не передаётся в URL; браузерные Origin отклоняются.
- **Токен даёт полномочия управлять твоими агентами**, включая их обычные инструменты. Это не read-only доступ. Хранить как пароль; не публиковать APK с токеном (в этой сборке токена нет).
- Для отзыва доступа заменить файл `device-token` новым криптографически случайным секретом длиной не менее32 символов и выполнить `launchctl kickstart -k gui/$(id -u)/ru.billyhargrove.pi-mobile`. Обновить токен на доверенных устройствах.
- Нет автоматического повтора команды после обрыва: результат может быть неопределённым, сначала проверить чат.
- Независимый security-аудит не проведён; это персональный MVP, не многопользовательский сервис.

## Ограничения MVP

- Передаются последние200 сообщений активной ветки (до400 UI-записей с отдельными tool calls); длинный текст ограничен30 тыс. символов, аргументы инструмента —8 тыс. Обрезка отмечается.
- PNG/JPEG/WebP, до3 картинок и10MB суммарно на сообщение. Картинки инструментов видны, если Pi вернул ImageContent; произвольные файлы по пути с диска не публикуются.
- Кэш картинок ограничен128MB на сервере, может вытесняться; старое изображение тогда недоступно. Полноэкранный просмотр масштабирует декодированное изображение (длинная сторона до1600px), без скачивания исходного файла.
- Approval-диалоги и произвольные UI расширений остаются в терминале. Нет создания нового Pi или переключения веток с телефона.
- После обновления расширения существующие Pi требуют `/reload` в свободном состоянии. Смена модели/effort во время работающего агента отклоняется. При сетевом обрыве результат конфигурации может быть неизвестен; проверь текущее значение перед повтором.
- Состояние раскрытых tool calls сохраняется в текущем экране при стриминге, но не после пересоздания Activity. Вложенные вызовы инструментов показываются по live-событиям; их подробный вывод не восстанавливается из истории Pi после перезапуска.
- Нет push-уведомлений и гарантированной постоянной связи в Android background. При возвращении приложение переподключается и загружает текущую историю.
- Репликация рабочих пространств означает каталог и существующие живые диалоги, не полный интерфейс Orca/редактор файлов.
