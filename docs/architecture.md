# Architecture map — Pi Mobile

**Current version:** `v0.6.008`, Kotlin/Compose compact UI, Queue and workflows, Node gateway and Pi extension. The left drawer is removed; direct catalog/history/settings and chat-back navigation remain. No lower Toast/Snackbar notifications: owner state renders feedback inline, transcription is a composer spinner, and effort/model/tier panels require user dismissal. All Android production source is Kotlin; bounded Markwon/LaTeX and image zoom are documented native leaves. Exact ownership is machine-checked. The [goal](../loop-develop/current-todo/001-todo.md) still requires physical-device acceptance. Billy authorized the release and APK delivery after the [local verification](release-0.6.004.md); live Pi/Orca/gateway remain untouched.

The fifteen updater/voice/chat/media architecture slices below are integrated in [release0.6.008](release-0.6.008.md). Their operation counts describe bounded scenarios, not whole-app FPS, CPU or battery measurements. Request retirement remains local and never silently replays or cancels Pi work.

Queue is an app-local receipt projection owned by ChatOutbox/ChatSession, not a global scheduler: ACK is acceptance, a new matching canonical echo consumes one entry. OrchestrationEntry's existing facade exposes guarded live snapshots/active presentation, while OrchestrationActivity composes feature-owned phase/agent drill-down. Compose owns chat overlay/system/IME insets; other screens keep their existing inset path. PiTranscript projects a receipt only for the latest user entry and rolls the latest actual tool name/count without an aggregate failure label. Hiding the main-chat older-history banner does not remove truncation metadata/history paging. Quick effort ACK guarding survives the removal of its pending label. The local updater slice keeps `ui/AppUpdates` as the catalog-facing lifecycle facade. Internal `features/updater/UpdateSession` owns request identity, dismissal, monotonic progress and explicit permission return through injected main-thread ports; `UpdateScreen` renders the unchanged modal geometry. `net/ReleaseClient` independently reads public GitHub metadata (1 MiB bound) and streams APKs (exact metadata size, max 32 MiB), with checked redirects, owned cancellation and unique partial files. `ui/UpdateInstaller` retains package/newer-version/exact-signing-certificate checks and the scoped FileProvider. Cancel/close retire a ticket before aborting HTTP; late callbacks cannot write preferences, replace the next modal or launch Android. Later on permission drops the pending action; only explicit Open settings can arm resume, and failure never silently retries. [Verification and limits](architecture-updater-20261007.md). The dated slice was verified before the bump and is now included in0.6.008/code15.

The local voice slice keeps public `ui/DictationRecorder` constructor/cancel/constants while moving state/deadline/control ownership into internal `features/voice/RecordingSession` and geometry into `RecordingScreen`. `media/PcmRecorder` owns a private PCM stream and the Android AudioRecord boundary; finish/cancel stop capture, the worker releases its source, and cancellation before delivery deletes its own file. At most one pending meter carries the latest sample time/RMS while UI is busy. Pure `core/PcmAudio` centralizes PCM16 mono/16kHz bounds and RMS, including HttpApi preflight rejection of odd byte lengths. The ready file belongs to the existing transcription/draft caller; recording cancellation cannot delete a file already handed off. [Verification and limits](architecture-voice-20261007.md). HTTP transcription after handoff and the chat send path retain their existing owners; capture itself never uploads or sends a Pi command.

The next speech handoff slice moves request/draft state into internal `features/chat/TranscriptionSession` and private PCM/worker/cancellation ownership into `net/SpeechTranscriber`. `HttpApi.transcribe` retains its blocking API and wire policy, delegating to an internal cancellable request. Activity composes credential snapshots and chat callbacks; onStop retains the request, onDestroy closes its owner before cancelling HTTP. Late/duplicate results cannot insert speech, show feedback or clear a newer spinner. Rejected files are discarded; active HTTP keeps its input file until the reader exits. Draft/cursor insertion delegates through the ChatSession facade to ComposerSession; no prompt is sent by transcription. [Verification and limits](architecture-transcription-20261008.md).

The local attachment slice adds internal `features/chat/AttachmentSession` as a platform-free picker/request owner and `media/AttachmentImporter` as the cancellable worker/staged-thumbnail owner. `media/AttachmentRead` bounds bytes while reading and closes its active stream on cancellation; `media/PickedAttachments` owns Android MIME/name/thumbnail adaptation, querying a display name once per item. Activity composes these ports and lifecycle only. `net/AttachmentPreparer` and public `ImagePreparer.prepare` retain their signatures. The image budget now honors the exact shared remainder rather than increasing it to64KiB; the batch independently checks each resulting payload. First failure retains the successful prefix and existing draft. onStop retains import; onDestroy retires its ticket before cancellation. Undelivered thumbnails are released; accepted values remain with ChatSession/ChatOutbox. [Verification and limits](architecture-attachments-20261008.md).

The local transcript slice moves canonical TranscriptStore/visible projection ownership into internal platform-free `features/chat/TranscriptSession`. ChatSession retains scoped events, epoch/history/connection/presence adaptation and its public items/toggle facade. The owner reuses each ChangeSet canonical snapshot through outbox overlay → receipt checkpoint → viewport publication → rendered signals, avoiding a second store copy. Shared pure `core/TranscriptPresentation.update` batches source/status/metadata, caches source topology/visible rows/tool membership and skips equal updates; settlement/manual disclosure remain independent. Snapshot status overrides metadata, epoch replacement resets disclosure, prepend has no arrival/tail signal, and optimistic receipts never satisfy canonical user context. Owned/published lists are read-only and caller source is copied. [Verification and limits](architecture-transcript-20261008.md).

The local composer slice moves draft text/editor identity, caret insertion, attachment list, preparation/transcription flags and restore/consumption policy into internal `features/chat/ComposerSession<Value, Attachment>`. Both value types are opaque: three injected editor operations adapt TextFieldValue in ChatSession, preserving external selection and IME composition without importing Compose UI or media. The unchanged public ChatSession facade feeds ChatComposer and I/O owners. A successful send consumes only its owner/revision snapshot, so reentrant edits (including change-and-back) survive; exact sent text/bytes remain with ChatOutbox. Empty preparation and invalid removal retain the published read-only attachment list. onStop retains draft/flags; onDestroy closes draft policy before cancelling I/O, retiring late callbacks without recycling attachments. Control ACK clears matching text only; rejection restores only an unoccupied draft. [Verification and limits](architecture-composer-20261008.md).

The local outbox slice extracts ordered canonical USER echo consumption into internal pure `features/chat/QueueProjection`. It collects user candidates in one canonical walk, bounds the saved-key suffix before mapping and retains unchanged receipt references. Public ChatOutbox owns revision-cached read-only receipt/queue lists and changed-only persistence through the existing injected ChatSession callback. Reservation before the port blocks duplicate reentry; a failed save remains retryable. Streaming/snapshots with unchanged receipts skip JSON serialization, while send/ACK/uncertain/restore/echo cleanup publish their new states. PendingMessages/codec preserve private host/session text records and their existing JSON equality check; queue acceptance and explicit retry/reconnect semantics remain unchanged. [Verification and limits](architecture-outbox-20261008.md).

The local viewport slice moves follow-tail, initial/cached restoration, reader-generation fencing, tail/arrival revisions, catch-up phases and new-activity disclosure into internal `features/chat/ViewportSession`. Typed position ports retain the existing signed offset/cache wire format; ChatSession preserves public Viewport/getters/actions and canonical presentation/scoped event adaptation. Manual reading prevents a delayed cached anchor from replacing the current viewport; the load is reserved before its port. Arrival comparison preserves new/changed/tool/expansion semantics in one pass without a temporary filtered list. Compose alone measures/animates/scrolls and keys asynchronous restoration/arrival effects by chat identity. Destroy retires transient signals, preserving saved positions and canonical data. [Verification and limits](architecture-viewport-20261008.md).

The local configuration request slice moves typed model/effort/tier submission, single-flight reservation, terminal/detached-ledger results and local close into internal `features/chat/ConfigurationSession`. ChatSession retains public configure/pending, scoped events, canonical JSON reports and transport adaptation. Panels retain field-specific draft/confirmed rollback; reports do not settle a ticket and ACK does not invent canonical configuration or completion. Setup errors release pending, destroy retires waiting and clears/dismisses both panels, and late effects cannot alter the destroyed screen. [Verification and limits](architecture-configuration-requests-20261008.md).

The local control slice moves typed `/mcp`/`/name` classification, capability/attachment/read-only policy, pending control/stop identity, data-once acceptance and detached-ledger reconciliation into internal `features/chat/ControlSession`. Stop is independent of the control ticket and single-flight until ACK/uncertain; ACK does not change canonical session status. ChatSession preserves its public send/abort API and scoped JSON adaptation. Pure `McpProjection` prepares immutable status text/time once per accepted reply; native timestamp formatting and the existing Material dialog remain in Activity. Activity owns one MCP window, rejects finishing/destroyed effects, clears its reference synchronously onDestroy and ignores dismissal from a replaced window. Missing MCP data keeps the command draft for explicit retry; ordinary terminal results clear only the matching submitted draft. Closing waiting never replays, cancels remotely or aborts Pi. [Verification and limits](architecture-controls-20261008.md).

The local history slice moves epoch/cursor/ticket, single-flight, page-once acceptance, ACK-gated automatic pagination, cursor-progress fences and detached-ledger reconciliation into internal `features/chat/HistorySession`. ChatSession keeps scoped JSON adaptation and its existing history API/loading state; Activity retires local waiting onDestroy. Failed or missing replies cannot cause a streaming-driven retry storm; a reader gesture can retry a failed page. Accepted cursors cannot repeat within a chain; an authoritative snapshot starts a fresh chain even within the same epoch, since it may replace an incompatible prefix. `core/TranscriptStore` maintains canonical user-context membership incrementally on live changes; history merge recalculates it after live-overlap precedence. Context checks no longer allocate/copy/scan the full transcript. Prepend still uses stable item keys without tail movement or arrival animation. [Verification and limits](architecture-history-20261008.md).

The local document slice moves read-only request identity, single-flight, data-once completion, cancellation and detached-ledger reconciliation into internal `features/chat/DocumentSession`. ChatSession retains its public document API and scoped transport/event boundary. `DocumentScreen` is presentation-only with an injected native Markdown leaf; public `ui/MarkdownPreview` retains its constructor, native modal and renderer cleanup. Closing the current window retires its awaited next file; dismissal from a replaced window cannot cancel a newer read. Activity rejects finishing/destroyed window effects and reuses a visible window for identical path/source, retaining actual scroll and one Markdown parse. Local cancellation sends no remote command and does not affect another chat capability. [Verification and limits](architecture-documents-20261008.md).

The local configuration-panel slice moves opening/fallback/editability policy, visible waiting-window result routing and local disposal into internal platform-free `features/chat/ConfigurationPanels`. Its typed ports carry projected Quick/Models data; Activity retains Android windows, IME/anchor geometry and explicit command callbacks. Public host constructors remain compatible. Quick configuration reports project only the selected valid model within the same 1000-entry registry bound, without a full catalog/map or unrelated capability arrays; partial reports do not read the registry. Explicit equal field reports still advance field-specific ACK fences. Model drafts retain their snapshot; confirmation never dismisses a panel. [Verification and limits](architecture-panels-20261008.md).

The local active-work slice adds shared pure `core/ActiveWork`: copied workflow/phase/agent facts, static counters, primitive clocks, navigation targets and history/live membership. ChatScreen projects one snapshot for both header and dock; internal chat presentation consumes typed facts. Public `ui/OrchestrationEntry` retains lifecycle discovery and the existing JSON ActiveOrchestration facade, adapting to internal presentation-only `features/orchestration/ActiveWorkScreen`. Elapsed ticks format primitive time without rereading JSON phases/clocks; recorded activity remains inspectable without becoming live work. Snapshot projection owns read-only lists; a new accepted snapshot updates facts. [Verification and limits](architecture-active-work-20261008.md).

The local transcript-image slice adds internal platform-free `features/chat/TranscriptImageSession` and presentation-only `TranscriptImageScreen`. Public `ui/PiTranscript` keeps TranscriptActions, read-only inspection, MediaLoader and native ImageViewer adapters. A binding belongs to both URL and loader identity; replacing the loader starts clean even with an unchanged URL. Reservation precedes the load port, only the first result publishes, and local retirement releases its reference while rejecting late callbacks without recycling shared cache pixels or cancelling another subscriber. Local attachment URLs never load remotely. Compose pixels retain the original aspect/size/feedback; fullscreen opening remains an injected callback. [Verification and limits](architecture-transcript-image-20261008.md).

## Product invariants

```text
Existing Pi/Orca process ← Unix bridge ← Node gateway (127.0.0.1, bearer, HTTPS proxy)
                                             ↕ explicit authenticated wire
                          Android app (same package/signature/preferences)
```

A screen never creates a second Pi or silently resends an uncertain command. Gateway owns server-side authorization, origins, bounded media/history, update and agent-inspection scope. Extension owns Pi-session-only configuration and the Pi API; a physical device receives strictly sanitized projections, not global defaults, raw session files or credentials. Preserve scheme/versionCode/signing and upgrade-in-place. See `docs/protocol.md`, `docs/setup.md` and security tests.

## Current ownership (source of truth)

Machine-readable ownership is [architecture/owners.json](../architecture/owners.json): app shell, catalog, chat, orchestration, voice, updater and UI foundation; platform packages are `core`, `net`, `store`, `media`. `ChatActivity.kt` is a lifecycle/platform composition root for feature-owned `features/chat/ChatSession` and Compose `ChatScreen`. ChatSession owns scoped event/JSON adaptation and configuration through an injected transport; TranscriptSession owns the canonical transcript and visible shared projection; bounded request/viewport/draft owners retain their policy. `ChatOutbox` alone owns optimistic receipts, retained bytes, revision-owned publication and explicit retry/restore; reconnect never replays a prompt. Kotlin PendingMessages/PendingMessageCodec read the existing private host/session records. Compose ChatScreen owns reader geometry/canvas; internal ChatHeader, ChatComposer and ChatWorkDock own header/notices, draft/attachments/delivery and work/Queue/skills. Shared PiIconButton and pure AgentMetrics retain existing state owners. [Review, scoped lifecycle fixes and chat arrival behavior](review-architecture-20261007.md). The old Java chat adapter, widgets and XML were removed with their callers.

`OrchestrationActivity.kt` is the lifecycle/navigation/IO composition shell for `features/orchestration/OrchestrationSession`, pure `OrchestrationProjection` and Compose `OrchestrationScreen`. The injected read-only transport has no command API or credentials. Session owns loading, stale/error notices, generation/request guards, source/cursor merging and disclosure/follow-tail revisions; the UI alone owns scroll geometry. Screen consumes `ui/PiTranscript` without optional main-chat actions. Snapshot aggregation keeps static workflow tool/token metrics out of the live duration ticker. [Local decomposition, measured counter and next slices](architecture-work-20261007.md); no new release or live-host deployment. `core/TranscriptPresentation` is the single normalization/disclosure/settlement policy. Markdown/LaTeX remains a bounded Markwon TextView leaf and fullscreen media retains the platform zoom viewer. Model/tier and quick effort state/rendering are internal ModelSettingsSession/Screen and QuickEffortSession/Screen; pure ModelCapabilities is shared by both panels, EffortSlider and TierToggle. ModelSettingsSheet/EffortPopup retain modal/anchor/lifecycle only. [Configuration slice and checks](architecture-configuration-20261007.md). Document preview, bubble picker, RMS dictation and update dialogs have Compose content. Native hosts are bounded platform modal/anchor owners; the brain slider uses its shared Compose Canvas. `ui/OrchestrationEntry.kt` has an injected read-only fetcher and lifecycle generation guard. `MainActivity.kt` composes injected `features/catalog/CatalogSession` and Compose `CatalogScreen`, including direct history navigation and grouped settings. ChatSession owns dismissible inline notice state; model configuration ACK re-enables the current panel rather than closing it. Internal ArchiveSession/UsageSession own guarded search, pagination, pending deletion, polling and selection through injected ports; ArchiveProjection/UsageProjection prepare immutable rows once per response and ArchiveScreen/UsageScreen contain only presentation. ArchiveSheet/UsageCards retain the existing Android facade. [Catalog decomposition and checks](architecture-catalog-20261007.md). All production Android sources are Kotlin; legacy adapters, Java widgets and screen XML were removed. Integrated build/Node/JVM and all synthetic UI cases have passing coverage across the full run and focused fixes. Display/motion, actual read-only relay and emulator upgrade/rollback passed; physical-device acceptance remains open. No extra Gradle modules or DI framework are required. `node tools/check-architecture.mjs` refuses unowned sources, Java/Kotlin twins, cross-capsule implementation imports and reversed platform dependencies.

Node lanes: `contracts/` owns pure shared payload projection; `extension/` observes active Pi and transports bounded snapshots over a private bridge; `server/` owns loopback gateway, persistence, REST/WSS and policy. Both host runtimes may depend on `contracts/`; they must not import each other's implementation. `contracts/agent-transcript.mjs` is the shared transcript seam; `contracts/command-receipts.mjs` shares bounded mutation-only deduplication without caching read payloads; `server/command-policy.mjs` validates bounded commands/images; `server/message-projection.mjs` turns private Pi messages into ordered, bounded, path-sanitized public rows; `server/media-cache.mjs` owns in-memory evicting image bytes; `server/session-projection.mjs` isolates allowlisted configuration/page metadata and checkpointed snapshot/delta frames from the gateway event loop. No source file in `contracts/` imports either runtime. Checks are additive and fail on new violations rather than hiding debt behind a growing baseline.

The ownership guard also covers feature-owned files in the shared `ui/` namespace. `publicFeatureApis` declares file-level facades; `compositionRoots` limits Activity navigation and app-shell access. The checker derives top-level Kotlin exports and checks explicit/wildcard imports, aliases, qualified references and same-package references. Comments and literal text do not create dependencies; interpolation expressions still count. `ui/StatusUi` is shared generic presentation. Only the existing ImageViewer/ArchiveSheet platform dependencies are registered separately. `sourceContracts` additionally assigns the orchestration and catalog state/projection/screen platform-free, pure and presentation-only profiles. Reversed profiled dependencies (including same-package references) and transport/platform imports fail; only Compose runtime for state and MediaLoader for the screen are bounded exceptions. Unknown contracts/unowned contract sources fail closed. This is a bounded source guard alongside compilation and behavior checks, not reflection analysis. See the [final acceptance audit](../loop-develop/slices/006-final-acceptance-audit.md) for the remaining physical-device and Linux-session checks.

## Desired dependency direction

```text
Android thin app shell → feature public APIs → core protocol/session/media/storage and UI tokens
                      no feature → another feature's implementation
Gateway composition → bounded server capabilities → pure shared contracts
Pi extension adapter → Pi lifecycle + pure shared contracts
```

Start as source-package ownership; add Gradle modules only if they buy tested isolation and independent ownership. Work per vertical user journey, not by renaming folders. The app shell composes navigation/lifecycle, features own screen state and errors, core owns stable domain-neutral primitives. Backend transport accepts only bounded versioned DTOs; unavailable provider capability remains unavailable, never inferred from a global setting. No direct Android UI import from gateway or Pi extension.
