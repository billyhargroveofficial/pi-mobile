## Product invariants

```text
Existing Pi/Orca process ← Unix bridge ← Node gateway (127.0.0.1, bearer, HTTPS proxy)
                                             ↕ explicit authenticated wire
                          Android app (same package/signature/preferences)
```

A screen never creates a second Pi or silently resends an uncertain command. Gateway owns server-side authorization, origins, bounded media/history, update and agent-inspection scope. Extension owns Pi-session-only configuration and the Pi API; a physical device receives strictly sanitized projections, not global defaults, raw session files or credentials. Preserve scheme/versionCode/signing and upgrade-in-place. See `docs/protocol.md`, `docs/setup.md` and security tests.

## Current ownership (source of truth)

Machine-readable ownership is [architecture/owners.json](../architecture/owners.json): app shell, catalog, chat, orchestration, voice, updater and UI foundation; platform packages are `core`, `net`, `store`, `media`. `ChatActivity.kt` is a lifecycle/platform composition root for feature-owned `features/chat/ChatSession` and Compose `ChatScreen`. ChatSession owns canonical transcript, scoped ACK/control/history/configuration, epoch guards and follow-tail through an injected transport. `ChatOutbox` alone owns optimistic receipts, retained bytes and explicit retry/restore; reconnect never replays a prompt. Kotlin PendingMessages/PendingMessageCodec read the existing private host/session records. Compose ChatScreen owns reader geometry/canvas; internal ChatHeader, ChatComposer and ChatWorkDock own header/notices, draft/attachments/delivery and work/Queue/skills. Shared PiIconButton and pure AgentMetrics retain existing state owners. [Review, scoped lifecycle fixes and chat arrival behavior](review-architecture-20261007.md). The old Java chat adapter, widgets and XML were removed with their callers.

`OrchestrationActivity.kt` is the lifecycle/navigation/IO composition shell for `features/orchestration/OrchestrationSession`, pure `OrchestrationProjection` and Compose `OrchestrationScreen`. The injected read-only transport has no command API or credentials. Session owns loading, stale/error notices, generation/request guards, source/cursor merging and disclosure/follow-tail revisions; the UI alone owns scroll geometry. Screen consumes `ui/PiTranscript` without optional main-chat actions. Snapshot aggregation keeps static workflow tool/token metrics out of the live duration ticker. [Local decomposition, measured counter and next slices](architecture-work-20261007.md); no new release or live-host deployment. `core/TranscriptPresentation` is the single normalization/disclosure/settlement policy. Markdown/LaTeX remains a bounded Markwon TextView leaf and fullscreen media retains the platform zoom viewer. Model/tier and quick effort state/rendering are internal ModelSettingsSession/Screen and QuickEffortSession/Screen; pure ModelCapabilities is shared by both panels, EffortSlider and TierToggle. ModelSettingsSheet/EffortPopup retain modal/anchor/lifecycle only. [Configuration slice and checks](architecture-configuration-20261007.md). Document preview, bubble picker, RMS dictation and update dialogs have Compose content. Native hosts are bounded platform modal/anchor owners; the brain slider uses its shared Compose Canvas. `ui/OrchestrationEntry.kt` has an injected read-only fetcher and lifecycle generation guard. `MainActivity.kt` composes injected `features/catalog/CatalogSession` and Compose `CatalogScreen`, including direct history navigation and grouped settings. ChatSession owns dismissible inline notice state; model configuration ACK re-enables the current panel rather than closing it. Internal ArchiveSession/UsageSession own guarded search, pagination, pending deletion, polling and selection through injected ports; ArchiveProjection/UsageProjection prepare immutable rows once per response and ArchiveScreen/UsageScreen contain only presentation. ArchiveSheet/UsageCards retain the existing Android facade. [Catalog decomposition and checks](architecture-catalog-20261007.md). All production Android sources are Kotlin; legacy adapters, Java widgets and screen XML were removed. Integrated build/Node/JVM and all synthetic UI cases have passing coverage across the full run and focused fixes. Display/motion, actual read-only relay and emulator upgrade/rollback passed; physical-device acceptance remains open. No extra Gradle modules or DI framework are required. `node tools/check-architecture.mjs` refuses unowned sources, Java/Kotlin twins, cross-capsule implementation imports and reversed platform dependencies.

Node lanes: `contracts/` owns pure shared payload projection; `extension/` observes active Pi and transports bounded snapshots over a private bridge; `server/` owns loopback gateway, persistence, REST/WSS and policy. Both host runtimes may depend on `contracts/`; they must not import each other's implementation. `contracts/agent-transcript.mjs` is the shared transcript seam; `contracts/command-receipts.mjs` shares bounded mutation-only deduplication without caching read payloads; `server/command-policy.mjs` validates bounded commands/images; `server/message-projection.mjs` turns private Pi messages into ordered, bounded, path-sanitized public rows; `server/media-cache.mjs` owns in-memory evicting image bytes; `server/session-projection.mjs` isolates allowlisted configuration/page metadata and checkpointed snapshot/delta frames from the gateway event loop. No source file in `contracts/` imports either runtime. Checks are additive and fail on new violations rather than hiding debt behind a growing baseline.

The ownership guard also covers feature-owned files in the shared `ui/` namespace. `publicFeatureApis` declares file-level facades; `compositionRoots` limits Activity navigation and app-shell access. The checker derives top-level Kotlin exports and checks explicit/wildcard imports, aliases, qualified references and same-package references. Comments and literal text do not create dependencies; interpolation expressions still count. `ui/StatusUi` is shared generic presentation. Only the existing ImageViewer/ArchiveSheet platform dependencies are registered separately. `sourceContracts` additionally assigns the orchestration and catalog state/projection/screen platform-free, pure and presentation-only profiles. Reversed profiled dependencies (including same-package references) and transport/platform imports fail; only Compose runtime for state and MediaLoader for the screen are bounded exceptions. Unknown contracts/unowned contract sources fail closed. This is a bounded source guard alongside compilation and behavior checks, not reflection analysis. See the [final acceptance audit](../loop-develop/slices/006-final-acceptance-audit.md) for the remaining physical-device and Linux-session checks.

## Desired dependency direction

```text
Android thin app shell → feature public APIs → core protocol/session/media/storage and UI tokens
                      no feature → another feature's implementation
Gateway composition → bounded server capabilities → pure shared contracts
Pi extension adapter → Pi lifecycle + pure shared contracts
```

Start as source-package ownership; add Gradle modules only if they buy tested isolation and independent ownership. Work per vertical user journey, not by renaming folders. The app shell composes navigation/lifecycle, features own screen state and errors, core owns stable domain-neutral primitives. Backend transport accepts only bounded versioned DTOs; unavailable provider capability remains unavailable, never inferred from a global setting. No direct Android UI import from gateway or Pi extension.
