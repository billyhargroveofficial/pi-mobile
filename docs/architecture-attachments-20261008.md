# Подготовка вложений — 8 октября 2026

Локальный последовательный слайс после декомпозиции обновлятора, записи и
транскрипции. Импорт выбранных документов вынесен из `ChatActivity`; исправлен
выход за общий лимит при маленьком остатке бюджета. Версия0.6.007/code14,
пакет, сертификат и зависимости сохранены. Публикация не выполнялась.

## Изменения и владельцы

`features/chat/AttachmentSession` владеет одной партией выбора: read-only,
свободными слотами, single-flight, окончанием подготовки и идентичностью
результата. URI и вложения передаются через типизированные порты без зависимости
от Android/media/net/UI. Владелец зарегистрирован в owners/sourceContracts;
новый отрицательный Node-тест запрещает обратные зависимости, включая URI,
ContentResolver, Bitmap и транспорт.

`media/AttachmentImporter` выполняет партию в фоновом executor. Он уменьшает
бюджет после каждого принятого файла, независимо проверяет размер результата и
прекращает партию на первой ошибке. Успешный префикс передаётся владельцу один
раз. До принятия результата превью принадлежат importer; отмена, отказ владельца,
ошибка доставки или фатальная ошибка worker освобождают неподтверждённые превью.
После передачи их владелец — существующий ChatSession/ChatOutbox: закрытие
подготовки не уничтожает уже добавленные изображения.

`media/AttachmentRead` ограничивает размер непосредственно при чтении. Для
обычного файла хватает чтения первого байта сверх доступного бюджета, чтобы
отклонить его; остальной файл не накапливается. Поток закрывается один раз на
успехе, ошибке и отмене, включая гонку отмены с открытием. Отмена партии закрывает
её текущий поток; queued cancel вообще не открывает URI.

`media/PickedAttachments` содержит ContentResolver/MIME/имя/Bitmap-адаптацию.
Имя каждого выбранного документа запрашивается один раз: прежняя цепочка для
обычного файла делала два запроса. Ограничение имени до200 символов применяется
до построения очищенной строки; замена разделителей/управляющих символов,
неизменяемые payload и пропорциональные превью сохранены. Public API
`net/AttachmentPreparer.prepare` и `media/ImagePreparer.prepare` остались прежними;
первый теперь совместимый тонкий фасад над media-адаптером.

`ChatActivity` связывает Android picker, executors, порты и lifecycle. Метод
`picked` сокращён с цикла чтения/подготовки/доставки до передачи выбора и текущих
ограничений владельцу. Activity содержит252 строки вместо259 в начале этого
слайса. Production Android:115 Kotlin-файлов,0 Java; Java ContentProvider для
проверки находится исключительно в instrumentation APK.

## Ошибка бюджета и сохранённое поведение

Раньше `ImagePreparer` увеличивал любой остаток меньше64KiB до64KiB. Например,
при остатке4 байта небольшое PNG проходило подготовку и превышало общий лимит,
хотя последующая отправка могла отклонить payload. Теперь положительный остаток
используется точно; нулевой/отрицательный бюджет отклоняется до открытия URI.
Batch дополнительно проверяет результат независимо от платформенного адаптера.
Лимит wire остаётся3 вложения и10MiB суммарных декодированных байтов; существующая
верхняя граница исходных image-байтов10MiB+1 сохранена.

Первая ошибка сохраняет уже подготовленные файлы и прежние вложения. Текст и
курсор принадлежат ChatSession, подготовка их не заменяет; пользователь может
редактировать текст во время импорта. Attach/send/remove блокируются прежним
флагом подготовки и снова доступны после результата. Ошибка остаётся inline.
Выбор сверх свободных слотов сообщает прежний лимит и берёт только доступный
префикс. Read-only не запускает импорт. Подготовка не отправляет prompt.

onStop сохраняет текущую работу и допускает результат для того же черновика в
фоне. onDestroy сначала снимает ticket, затем отменяет IO. Запоздалый/повторный
callback не добавляет вложения, не показывает старую ошибку и не снимает занятость
нового экрана. Принятые файлы сохраняют существующие правила outbox/retry/restore.

## Границы

Проверка synthetic content-provider проходит через настоящий Android IO, но не
проверяет системный documents picker, сторонний облачный provider или физический
телефон. Закрытие stream и проверки отмены не гарантируют мгновенное прерывание
неотзывчивого provider внутри getType/query/open или native Bitmap codec;
результат такой операции всё равно не попадёт в закрытый черновик. Бинарные
черновики по-прежнему не переносятся через destruction/recreation Activity и
не сохраняются на диск; этот слайс не вводит новое хранение файлов или автоповтор.
Live отправка/host deployment/релиз не выполнялись.
