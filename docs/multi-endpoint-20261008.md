## Пользовательский сценарий

- Нажать адрес в шапке каталога → **Computers**. Показаны имена, адреса, выбранный/подключённый хост и отсутствие токена, но не сами секреты.
- **Add computer** открывает пустые имя, URL и токен. **Save & connect** проверяет и атомарно сохраняет подключение, затем открывает мобильное соединение.
- Выбор сохранённой строки переключает компьютер. Повторный выбор уже подключённого хоста ничего не переподключает.
- Кнопка редактирования в строке открывает его данные, не переключая активный компьютер до **Save & connect**. Секрет не подставляется в поле; пустое поле сохраняет только токен этого же канонического URL.
- Settings → **Saved computers** открывает тот же выбор. **Forget this computer** требует локального подтверждения. Отмена не меняет данные; удаление активного подключения оставляет телефон отключённым, без автоматического выбора другого.
- Переключение/удаление параметров не отправляет `abort`, `close`, `delete`, `new`, `resume` или промпт. Работа и история на обоих компьютерах продолжаются независимо.

## Владельцы и хранение

`core/ConnectionProfile` содержит только безопасные метаданные. `features/catalog/CatalogSession` владеет выбором, формой, подтверждением удаления и поколениями ожиданий; внутренний `ComputerPicker` — только Compose-представление. MainActivity адаптирует эти порты к SettingsStore/PiClient.

Внутренний `store/ConnectionProfiles` валидирует JSON версии1, UUID/имя/адрес/границы и выполняет транзакции через storage/cipher-порты. `SettingsStore` одним `SharedPreferences.commit` сохраняет `connection_profiles_v1` и совместимое активное зеркало `base_url` / `token_gcm`. Неуспешный commit пытается восстановить прежнее видимое состояние и не запускает соединение. Plaintext-токен в preferences, UI-модель, Intent/Bundle, URL и отчёт не попадает.

Токены каждого подключения отдельно зашифрованы прежним AES256-GCM/AndroidKeyStore `SecureTokenStore` с тем же alias. **Нельзя удалять общий Keystore key при очистке одного профиля.** Нечитаемый cipher снимает токен только этого компьютера; остальные записи сохраняются. Нечитаемый/будущий JSON отклоняется без использования его legacy-токена и без перезаписи сырого blob; автоматический сброс данных не предусмотрен.

Legacy-подключение читается как один профиль `legacy` без немедленной перезаписи настроек. Первый явный save/select переносит прежний ciphertext и исходное написание URL, сохраняя существующее пространство outbox. Сравнение адресов каноническое: scheme/host/default port/trailing slash, но путь и нестандартный порт различают endpoints. Один канонический URL — одна запись; смена адреса не переносит предыдущий секрет.

Ограничения: до32 компьютеров, имя до80 символов, URL до4096, токен до16384, cipher envelope до65536, профильный JSON до2MiB. HTTPS обязателен на телефоне; существующее debug-исключение HTTP только для loopback эмулятора сохранено. Порты0 и выше65535 отклоняются до создания OkHttp socket.

## Разделение хостов и lifecycle

Один активный мобильный socket, не фоновый объединённый каталог. При смене компьютера каталог/ожидающие refresh/health/launch/подтверждение/локальные mutation callbacks инвалидируются. Usage останавливается, история закрывается, media cache сменяет credential scope. Неизвестные результаты прошлых команд не повторяются. Возврат в каталог без активного токена не воскрешает каталог забытого клиента.

PiClient сбрасывает старые subscription, snapshot, configuration и catalog; существующие WS identity и pending-ledger guards отвергают прежний socket, а кеш остаётся endpoint/token/session scoped. `PendingMessages` сохраняет прежний приватный host/session формат и не становится общей или автоматически повторяемой очередью.

ChatActivity/OrchestrationActivity записывают только непрозрачный endpoint/token digest, не секрет, в Intent/saved state. Старое окно при несовпадении scope закрывается, не подписываясь на одноимённую сессию другого компьютера; chat transport также отклоняет чужой клиент. HTTP/диктовка/инспекция и MediaLoader держат захваченные credentials, не динамически берут настройки другого хоста. Навигация/image viewer не переоткрывают прежний URL/agent на новом scope. Старое восстановление без записанного scope и с несколькими профилями отклоняется, а не угадывает хост. Digest кешируется, чтобы потоковые guards не расшифровывали токен на каждом кадре.

## Границы приёмки

Физический телефон, реальные несколько удалённых gateway и смена их сетей/токенов остаются для отдельной приёмки. Нативные тесты используют реальные Keystore/Activity/Compose/WS dispatch, но синтетические подключения и не выполняют платные промпты. Нет обещания одновременного мониторинга всех хостов, whole-app FPS/battery improvement или безусловного восстановления SSH/Pi. Gateway/protocol/extension, работающие Pi/Orca/relay и опубликованный APK не менялись.
