# Владелец черновика — локальный слайс 8 октября 2026

`ComposerSession<Value, Attachment>` отделяет ввод от канонической переписки и транспорта. `ChatSession` сохраняет публичные composer/attachments/preparing/transcribing, send/restore/dictation/skill APIs и адаптирует TextFieldValue тремя операциями редактора: текст, начало выделения и создание значения с курсором. Полное внешнее значение сохраняется без пересборки, включая оба конца выделения, AnnotatedString и IME-композицию. Владелец не импортирует Android, Compose UI, media, HTTP или хранилище; существующий platform-free-state контракт проверяет эту границу.

Отправка берёт текст и read-only список вложений из одного снимка. После успешной записи очищается только совпадающая версия того же владельца: новый текст, изменение выделения/композиции или удаление/повторное добавление файла сохраняют текущий черновик. ChatOutbox продолжает владеть именно отправленными данными, optimistic receipts, ACK, queue, explicit retry/restore и приватным форматом. Ошибка записи сохраняет черновик. Совпадающий control ACK очищает только текст; отклонённый prompt возвращает текст лишь в незанятый composer. Пробелы, вложения и подготовка считаются занятостью для restore; whitespace-only ввод сохраняет прежний режим микрофона.

Пустые подготовленные batches и индексы вне списка завершаются до concat/filter и публикации. Публикуемые непустые списки read-only; внешний список restore копируется, сами Attachment/bytes/thumbnail остаются прежними объектами. Проверка идентичности опубликованного списка подтверждает стабильность состояния, **не измеряет выделения памяти**: прежняя Compose structural-equality policy тоже могла сохранить старую ссылку после временной аллокации. Здесь устранение ненужных concat/filter проверяется по явным ранним guards; замеров FPS, heap или общей скорости приложения нет.

Диктовка сохраняет прежние правила вставки: selection.start с ограничением длиной текста, пробел перед распознанным текстом при позиции >0, без замены выделенного диапазона и без автоотправки. Busy flags остаются на stop/start. Activity.onDestroy закрывает composer до отмены импортера/транскрибации: запоздалые text/prepared/dictation/skill callbacks не меняют его данные, busy flags сброшены, отправка и restore закрыты. Владелец не кодирует, не загружает, не удаляет и не recycle-ит файлы/bitmap. Recreation по-прежнему сохраняет текст и оба конца выделения в Bundle; файлы и IME-композиция не обещаны после recreation/process death.

## Воспроизведение

Новый JVM regression на прежнем коде: после синхронного callback из prompt, записавшего `Next draft` и `next.md`, ожидался новый текст, получался пустой composer. Native fixture на прежнем APK повторил это через реальную кнопку Send: один optimistic bubble `Submitted draft`, следующий черновик исчез. На новом APK остаются `Next draft`, курсор4 и chip `next.md`, в transport ровно один prompt с `Submitted draft` и без следующего файла. Это проверка защитного поведения при reentry, не утверждение о частоте такого callback в реальном PiClient. Старый APK дополнительно прошёл busy/stop-start/dictation case перед сравнением снимков.
