# Pi Mobile protocol (v0.5.1 implementation contract)

## Additions in 0.5.1

- `new`: command envelope with a UUID `sessionId` generated by the client and `workspaceId` from inventory. Creates one visible local Orca terminal running `pi --session-id <id>`, no prompt. Durable private `new-session-intents.json` fences ambiguous launches; ACK has `data:{type:'resume',sessionId,terminalId,reused}`. Wait for connected catalog entry, not just ACK.
- `close`: `{command:'close',sessionId,requestId,confirm:true,force?:boolean}`. Fresh complete inventory and live owner required; `force:true` required if running. Closes only the exact terminal handle (never a whole split tab). Does not delete the session file. ACK data type `closed`.
- `delete`: `{command:'delete',sessionId,requestId,confirm:true}`. Irreversible unlink of the server-discovered archive file. Refuses live/pending/unknown owners and incomplete inventory; checks no-follow regular file, header id/cwd and unchanged inode. No client file paths. ACK data type `deleted`.
- `name`: validated non-empty `name`, up to200 chars; changes Pi session name, not Orca tab title. `mcp`: read command returning sanitized real adapter state with `observedAt`. Configuration advertises `capabilities` and bounded `skills` from Pi registry. Explicit `$skill` prefixes expand only known skills.
- Prompt accepts optional `files:[{name,data:<canonical base64>}]`. Files and images together: ≤3 and ≤10MiB decoded. Gateway stores content-addressed regular files under private `uploads/` (0600; quota256MiB), adds their local paths to the prompt and removes binary file payload before forwarding to Pi. User-message presentation replaces these generated paths with `📎 filename`. No arbitrary file download route.
- `POST /api/transcribe`: same bearer/origin rules; JSON `{sampleRate:16000,audio:<base64 PCM16LE mono>}`, 0.1–60 seconds, request ≤3MiB. Returns `{text}`. One recognition at a time (429 if busy); no Pi command is dispatched. Uses installed local Orca sherpa-onnx/Parakeet files in an ephemeral worker, not Orca's paired-mobile RPC or a cloud provider. No automatic audio retry, model download or settings mutation.
- Android renders progress messages separately between contiguous tool segments. Settled segments collapse once and remain manually expandable. ACK checks mean acceptance, never task completion/read-by-human. Local unconfirmed text receipts survive screen re-entry without replay; binary drafts are not persisted. If the 40-message tail contains no user prompt, preceding pages are fetched until user context appears.


Catalog membership is now authoritative Orca visible layout membership, not gateway registration history. Only connected, non-orphan Pi terminal handles contained in `terminal list --include-visual-layouts` are shown. Connected bridge owners attach to those handles; unbridged handles remain read-only rows. Closed/off-layout sessions are omitted; empty workspaces remain visible for creating sessions. Inventory refreshes every3 seconds; failures retain the last known inventory with `inventoryError`.

`GET /api/archive?offset=0&q=<query>` (same bearer/origin rules) lists up to40 saved session metadata records, newest first, with `hasMore,nextOffset`. Entries expose id/title/cwd/workspace/modified/messageCount, never launch commands or session file paths. Sources are Pi SessionManager's standard session store for known local Orca workspaces; custom session directories and remote workspaces are not scanned. Live bridge owners are excluded. The list is cached15 seconds.

`{type:'command',command:'resume',sessionId,requestId}` resumes a server-discovered session. Client-supplied paths/commands are ignored. Ack data: `{type:'resume',sessionId,terminalId,reused}`; this acknowledges tab creation/reuse, not Pi readiness. Wait for the same session's connected catalog entry before opening chat. The server uses `orca terminal create` with a shell-quoted `pi --session <saved-file>` command, no prompt. The existing session header id/cwd must match. A live owner is reused; an owner outside visible tabs is not duplicated. Unknown unbridged Pi in that workspace, incomplete inventory, or ambiguous previous creation prevents another launch. Concurrent/repeated requests are single-flight; private durable resume intents survive gateway restart, with a30-second appearance grace. A failed/uncertain create is fenced until operator inspection. Same-request acknowledgments use normal receipt deduplication.

History starts with the last 40 source messages. Snapshot includes `history:{before,hasMore}`, `epoch`, `activeTurnId`, `turns:[{id,startedAt,finishedAt,outputTokens,generationMs}]`. Message records add `turnId`, `phase:'work'|'final'`, argument `preview` and optional `documentPath`. Epoch changes replace the transcript. Normal rolling-tail eviction does not remove already-loaded older rows. Reconnecting resets the client to the current tail.

Read-only WS commands use the same envelope/authentication: `command:'history',before:<cursor>,limit:40` or `command:'document',path:<md-path>`. Successful ack contains `data:{type:'history',messages,history,epoch,turns,...}` or `data:{type:'document',path,text}`. History records prepend with stable-ID deduplication, preserving live versions. Data replies are not stored in the command receipt cache. Missing cursors fail explicitly. Document paths resolve within the session's real cwd; only regular `.md`/`.markdown` files, up to1MiB, no NUL bytes, no symlink escape. No arbitrary-file route.

Turn metrics persist as Pi custom entries `pi-mobile-turn-v1`, not model messages. Duration spans agent start to settlement. TPS divides provider-reported output tokens by accumulated time from first assistant update to its completion, excluding tool execution. Historical metrics without recorded events remain unavailable. Android shows independently collapsible tool segments separated by standalone progress bubbles, with final answer outside. Native Markdown/LaTeX rendering does not execute HTML/JS or fetch external images.

Snapshot frames include `configuration: {model:'provider/id',thinkingLevel,models:[{provider,id,name,thinkingLevels:[string]}],modelsTruncated:boolean}`. Incremental messages frames include configuration only when it changes. Model capabilities come from the live Pi registry; no credentials, API keys or provider headers are exposed. The model list is limited to 1000 entries with an explicit truncation flag.

Tool-call UI records use `role:'toolResult'`, stable `id:'tool:<call-id>'`, `toolName`, `toolStatus:'pending'|'running'|'done'|'error'|'interrupted'`. Their text contains bounded arguments and cumulative output, not output deltas. Extension listens to `tool_execution_start/update/end`; a final result replaces the live record with the same ID. Assistant tool-call blocks are not duplicated as plain assistant text. Android defaults tools to collapsed, retains expansion during updates, and loads their images only when expanded. Nested tool output is live-only if absent from Pi's persisted message history.

Gateway default http://127.0.0.1:8788. Production HTTPS required; emulator debug may use http://10.0.2.2:8788. All /api and /ws require Authorization: Bearer <token>. Token NOT in URLs. /health is unauthenticated, no sensitive data. HTTP JSON errors {error:string}.

GET /api/catalog → {type:'catalog', workspaces:[{id,name,path}], sessions:[{id,title,cwd,workspaceId,terminalId,connected:boolean,status:'idle'|'running'|'offline',model:string}], terminals:[{id,title,workspaceId,agent,connected:false}]}. Unbridged terminals read-only, marked extension required. Workspaces reflect Orca identities, not just same cwd. Sessions outside visible Orca tabs are excluded from the main catalog.

GET /api/sessions/<encoded-id> → snapshot object.
WebSocket /ws (auth HEADER) immediately sends catalog. client sends {type:'subscribe',sessionId:string}. Server sends {type:'snapshot',sessionId,status,connected,messages:[{id,role:'user'|'assistant'|'toolResult'|'custom',text,images:[{url,mimeType}],toolName?:string}],truncated:boolean}. Snapshot replaces visible transcript for that ID. Subsequent updates are incremental frames {type:'messages',sessionId,messages:[changed or new complete message objects],removedIds:[string],status,connected,truncated}; upsert by message ID, remove removedIds, retain existing order and append new IDs. Updates are throttled to 100ms during generation. Images remain URL references rather than repeated base64. Every socket reconnect should resubscribe; requestId commands MUST NOT be auto-replayed.

Client command on WS: {type:'command',sessionId,requestId:UUID,command:'prompt',text:string,images?:[{type:'image',data:base64,mimeType:'image/png'|'image/jpeg'|'image/webp'}],behavior:'followUp'|'steer'}. Default followUp. Session configuration: {type:'command',sessionId,requestId,command:'configure',provider?:string,modelId?:string,thinkingLevel?:'off'|'minimal'|'low'|'medium'|'high'|'xhigh'|'max'}. Provider and modelId must be supplied together; at least a model or effort must be present. Extension rejects model changes on busy sessions, unavailable models and unsupported effort combinations BEFORE mutation; effort-only updates are allowed during a run and affect subsequent provider requests, not an already dispatched request. Changes apply only to this live session, never global defaults. No automatic replay. Abort {type:'command',sessionId,requestId,command:'abort'}. response {type:'ack',requestId,sessionId,ok:boolean,error?:string}. Ack is acceptance not completion; snapshot status tells activity. Preserve composer if ack fails. Timeout reported as uncertain, no automatic resend. Max 3 images / total 10MB decoded. Prompt/configure/abort commands target only the currently connected live process. Only explicit resume/new may launch a Pi session in Orca, with the duplicate protections above. No editing API, no arbitrary file routes.

Images are served by gateway at authenticated relative URL /api/sessions/<id>/media/<sha256>. Android must use same configured origin and auth header, never send token to other origins. Images no larger than 10MB. Do not parse HTML. Safe text rendering. Gateway caches binary payload separately; snapshot doesn't send repeated base64.

Local extension transport: Unix socket ~/.pi/agent/pi-mobile/bridge.sock mode 0600 parent 0700. JSONL max 32MB line. register {type:'register',meta:{id,title,cwd,pid,terminalId,workspaceId,model},messages:<Pi AgentMessage[]>,status}. snapshot {type:'snapshot',id,messages,status,meta?}; messages include pending assistant. command forwarded as above. result {type:'ack',requestId,ok,error?}. disconnect marks offline, never start another process. New session on same socket replaces prior session; duplicate live registration from another socket rejected. Initial history and subsequent pages contain up to40 source messages. Live nested events have a separate bounded cache (up to200); exceptionally large live tails can be truncated by the gateway's200-record normalization bound, with truncation reported. History pages have a20MB transport bound.
