# Pi Mobile protocol (v0.3 implementation contract)

History starts with the last 40 source messages. Snapshot includes `history:{before,hasMore}`, `epoch`, `activeTurnId`, `turns:[{id,startedAt,finishedAt,outputTokens,generationMs}]`. Message records add `turnId`, `phase:'work'|'final'`, argument `preview` and optional `documentPath`. Epoch changes replace the transcript. Normal rolling-tail eviction does not remove already-loaded older rows. Reconnecting resets the client to the current tail.

Read-only WS commands use the same envelope/authentication: `command:'history',before:<cursor>,limit:40` or `command:'document',path:<md-path>`. Successful ack contains `data:{type:'history',messages,history,epoch,turns,...}` or `data:{type:'document',path,text}`. History records prepend with stable-ID deduplication, preserving live versions. Data replies are not stored in the command receipt cache. Missing cursors fail explicitly. Document paths resolve within the session's real cwd; only regular `.md`/`.markdown` files, up to1MiB, no NUL bytes, no symlink escape. No arbitrary-file route.

Turn metrics persist as Pi custom entries `pi-mobile-turn-v1`, not model messages. Duration spans agent start to settlement. TPS divides provider-reported output tokens by accumulated time from first assistant update to its completion, excluding tool execution. Historical metrics without recorded events remain unavailable. Android groups tools and intermediate assistant commentary as flat virtualized rows in one collapsible work surface, with final answer outside. Native Markdown/LaTeX rendering does not execute HTML/JS or fetch external images.

Snapshot frames include `configuration: {model:'provider/id',thinkingLevel,models:[{provider,id,name,thinkingLevels:[string]}],modelsTruncated:boolean}`. Incremental messages frames include configuration only when it changes. Model capabilities come from the live Pi registry; no credentials, API keys or provider headers are exposed. The model list is limited to 1000 entries with an explicit truncation flag.

Tool-call UI records use `role:'toolResult'`, stable `id:'tool:<call-id>'`, `toolName`, `toolStatus:'pending'|'running'|'done'|'error'|'interrupted'`. Their text contains bounded arguments and cumulative output, not output deltas. Extension listens to `tool_execution_start/update/end`; a final result replaces the live record with the same ID. Assistant tool-call blocks are not duplicated as plain assistant text. Android defaults tools to collapsed, retains expansion during updates, and loads their images only when expanded. Nested tool output is live-only if absent from Pi's persisted message history.

Gateway default http://127.0.0.1:8788. Production HTTPS required; emulator debug may use http://10.0.2.2:8788. All /api and /ws require Authorization: Bearer <token>. Token NOT in URLs. /health is unauthenticated, no sensitive data. HTTP JSON errors {error:string}.

GET /api/catalog → {type:'catalog', workspaces:[{id,name,path}], sessions:[{id,title,cwd,workspaceId,terminalId,connected:boolean,status:'idle'|'running'|'offline',model:string}], terminals:[{id,title,workspaceId,agent,connected:false}]}. Unbridged terminals read-only, marked extension required. Workspaces reflect Orca identities, not just same cwd. Sessions outside Orca have cwd grouping.

GET /api/sessions/<encoded-id> → snapshot object.
WebSocket /ws (auth HEADER) immediately sends catalog. client sends {type:'subscribe',sessionId:string}. Server sends {type:'snapshot',sessionId,status,connected,messages:[{id,role:'user'|'assistant'|'toolResult'|'custom',text,images:[{url,mimeType}],toolName?:string}],truncated:boolean}. Snapshot replaces visible transcript for that ID. Subsequent updates are incremental frames {type:'messages',sessionId,messages:[changed or new complete message objects],removedIds:[string],status,connected,truncated}; upsert by message ID, remove removedIds, retain existing order and append new IDs. Updates are throttled to 100ms during generation. Images remain URL references rather than repeated base64. Every socket reconnect should resubscribe; requestId commands MUST NOT be auto-replayed.

Client command on WS: {type:'command',sessionId,requestId:UUID,command:'prompt',text:string,images?:[{type:'image',data:base64,mimeType:'image/png'|'image/jpeg'|'image/webp'}],behavior:'followUp'|'steer'}. Default followUp. Session configuration: {type:'command',sessionId,requestId,command:'configure',provider?:string,modelId?:string,thinkingLevel?:'off'|'minimal'|'low'|'medium'|'high'|'xhigh'|'max'}. Provider and modelId must be supplied together; at least a model or effort must be present. Extension rejects busy sessions, unavailable models and unsupported effort combinations BEFORE mutation; changes apply only to this live session, never global defaults. No automatic replay. Abort {type:'command',sessionId,requestId,command:'abort'}. response {type:'ack',requestId,sessionId,ok:boolean,error?:string}. Ack is acceptance not completion; snapshot status tells activity. Preserve composer if ack fails. Timeout reported as uncertain, no automatic resend. Max 3 images / total 10MB decoded. Commands scoped to currently connected live process only; never spawn second Pi. No editing API, no arbitrary file routes.

Images are served by gateway at authenticated relative URL /api/sessions/<id>/media/<sha256>. Android must use same configured origin and auth header, never send token to other origins. Images no larger than 10MB. Do not parse HTML. Safe text rendering. Gateway caches binary payload separately; snapshot doesn't send repeated base64.

Local extension transport: Unix socket ~/.pi/agent/pi-mobile/bridge.sock mode 0600 parent 0700. JSONL max 32MB line. register {type:'register',meta:{id,title,cwd,pid,terminalId,workspaceId,model},messages:<Pi AgentMessage[]>,status}. snapshot {type:'snapshot',id,messages,status,meta?}; messages include pending assistant. command forwarded as above. result {type:'ack',requestId,ok,error?}. disconnect marks offline, never start another process. New session on same socket replaces prior session; duplicate live registration from another socket rejected. Initial history and subsequent pages contain up to40 source messages. Live nested events have a separate bounded cache (up to200); exceptionally large live tails can be truncated by the gateway's200-record normalization bound, with truncation reported. History pages have a20MB transport bound.
