# Каноническая лента и общая проекция — локальный слайс 8 октября 2026

`TranscriptSession` выделяет каноническую переписку и видимые строки из ChatSession. Сетевые/scoped события, presence flags, status/loading/cache/truncation, JSON adaptation и epoch/history ticket остаются в прежних владельцах. Публичные `items`/`toggle` и интерфейс экрана сохраняются. Новый владелец содержит TranscriptStore и общую TranscriptPresentation, передаёт канонический snapshot через injected outbox overlay → receipt checkpoint → viewport publication → rendered signals. Используется ChangeSet.transcript, а не вторая копия TranscriptStore при том же обновлении. Prepend сохраняет порядок, canonical user-context и прежнее отсутствие arrival/tail сигналов; optimistic receipts не заменяют реальный USER-контекст истории. Checkpoint должен завершиться до публикации; исключение остаётся видимым вызывающему коду, канонические данные сохраняются для retry.

Общий pure `TranscriptPresentation.update` объединяет source/status/metadata в одной проекции. Сравнение owned source защищает от повторного legacy normalization/WorkTimeline build. Топология, видимые строки и membership списков инструментов пересоздаются только при изменении исходных сообщений; состояние завершения и manual disclosure применяется отдельно. Equal updates возвращают прежние items/row references. Status OFFLINE/IDLE по-прежнему сворачивает каждую группу один раз, повторные snapshots/metadata не отменяют ручное раскрытие. Epoch replacement явно reset-ит presentation даже при равном содержимом. Metadata присутствует лишь при передаче; authoritative snapshot/update status выигрывает у metadata.status. Сохраняются active-turn completion, progress/final stable keys, legacy fallback turn и обработка изменившихся file/image references.

Исходный список копируется внутри pure проекции. Канонические overlay inputs, published items и cached tool lists read-only; внешняя мутация не может испортить повторно используемые списки. Source equality остаётся O(n); retained snapshots расходуют память. Empty delta ещё проходит existing canonical/outbox publication, а receipt checkpoint сохраняет отдельную revision policy. Слайс **не устраняет всю работу на каждом frame** и не обещает измеренный FPS/heap/latency выигрыш.
